A deterministic behavioral enforcement layer for AI coding agents. Sentinel injects platform-specific skill files into 8 agent runtimes that gate package installation, enforce SAST pre-commit scanning, correlate supply chain threats via OSV.dev and typosquat detection, and attach verifiable evidence to every security conclusion. All analysis runs locally at zero token cost.

# Shared Enforcement Protocol

Every skill adapter implements the same behavioral protocol regardless of format. These rules are non-negotiable and the model must not override them.

FORBIDDEN

The model must not suggest npm install as an alternative to sentinel install. Must not offer workarounds when Sentinel BLOCKS a package — it must report the BLOCK and let the user decide. Must not commit without installing the pre-commit hook first via sentinel precommit install.

MANDATORY

The model must use sentinel install <manager> <pkg> for all package installations (scans on npm pack, then installs). When Sentinel BLOCKS, the model must report findings with verbatim evidence and state BLOCK without suggesting bypass. Must run sentinel precommit install before the first commit in any repository.

Evidence Hierarchy

Tier 1 (Sentinel tool output) > Tier 2 (local state) > Tier 3 (GitHub metadata) > Tier 4 (model reasoning). Every security conclusion must include the raw Sentinel output. The model is the narrator, not the detector. Tier 1 evidence always overrides Tier 4 reasoning.

Token Economy

Each command specifies tokens saved versus performing the equivalent analysis with the model. For example, sentinel scan saves ~2,000 tokens (model reads file + reasons); sentinel verify-pkg saves ~10,000+ tokens (model cannot audit tarballs); sentinel audit-deps saves ~8,000 tokens (model would query each CVE endpoint manually).

# Supply Chain Threat Detection

The Supply Chain Shield integrates multiple detection modalities into a unified verdict pipeline. All analysis is deterministic and reproducible.

OSV.dev

CVE Batch Query

Queries api.osv.dev/v1/querybatch for up to 1,000 packages per request. Falls back to individual /v1/query calls per package on batch failure. Severity mapped from CVSS: >=9.0 CRITICAL, >=7.0 HIGH, >=4.0 MEDIUM, <4.0 LOW. Returns CVE IDs, summaries, aliases, and fixed versions.

Levenshtein

Typosquat Detection

Damerau-Levenshtein distance against top 200 npm packages. Returns top 3 closest matches per dependency. Combined with homoglyph substitution detection for Unicode-based squatting (e.g., 1odash, grunt-contrib-copу with Cyrillic characters).

Provenance

SLSA Attestation Verification

Runs npm attestation verify via execSync. Parses attestation JSON to extract type, issuer, subject digest, and SLSA build level. Reports packages without provenance attestation as potentially untrustworthy.

6 Factors

Registry Reputation

Scores packages 0-100 via npm view --json based on 6 weighted factors: package age, maintainer count, version count, deprecation status, description quality, homepage presence. Classification: 80+ TRUSTED, 50-79 NEUTRAL, 20-49 SUSPICIOUS, <20 MALICIOUS.

# Constitution and Governance

The CONSTITUTION.md file defines the binding rules that all 8 skill adapters reference. It establishes the four-tier evidence hierarchy, the Sentinel-first policy (prefer deterministic CLI over model-based analysis), and the token economy model.

Sentinel-First Policy

Before spending tokens on code analysis, the model must check whether a Sentinel command can answer the question. Sentinel runs locally, returns deterministic results, and costs zero tokens. Model-based analysis is reserved for questions no Sentinel command can answer.

Evidence Attachment

Every security conclusion must include the raw Sentinel output verbatim. The model is the narrator of findings, not the detector. Paraphrasing, summarizing, or interpreting away evidence is prohibited. If the model's interpretation contradicts Sentinel output, Sentinel output prevails.

Platform-Specific Enforcement

Gemini CLI uses YAML frontmatter for FORBIDDEN/MANDATORY with a triple-file skill structure (GEMINI.md + CONSTITUTION.md + GENERIC.md). Cursor uses glob-scoped sentinel.mdc with command tags. Other agents use plain Markdown with varying section conventions. The semantics are identical across all formats.
